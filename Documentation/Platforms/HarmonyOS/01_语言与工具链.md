# HarmonyOS 语言与工具链决策

## 1. 推荐策略

| 层 | 默认选择 | 原因 | 仓颉的定位 |
|---|---|---|---|
| 应用 UI、Ability、系统 Kit 接入 | ArkTS + ArkUI | 官方主力语言与 UI 框架，工具/示例/API 覆盖最完整 | 仅在通过兼容性验收后用于独立试点；不要让一半页面 ArkTS、一半仓颉而没有模块边界 |
| 领域模型、同步协议 | JSON Schema / OpenAPI / fixtures | 与语言和平台无关，可被 Swift、Kotlin、ArkTS、仓颉共同验证 | 仓颉实现只是一个消费者 |
| 本地存储 | HarmonyOS RDB（关系型数据库） | 官方数据管理能力以 SQLite 为基础，适合结构化任务/使命/打卡数据 | 先确认仓颉插件/SDK 对所需数据 API 与异步模型的支持 |
| 原生高性能代码 | C/C++（若且仅若有实测瓶颈） | HarmonyOS 标准的 native 路线 | 不是把现有 Swift/GRDB 直接“编译过去” |

## 2. ArkTS 基线

HarmonyOS 官方开发导读和入门页将 ArkTS 作为优选应用开发语言、ArkUI 作为声明式 UI 框架、DevEco Studio 作为推荐 IDE。第一个产品工程应选 Standard Application、Stage 模型和 ArkTS 模板，采用单一 `entry` HAP 先验证基础架构；分包（feature HAP）、HAR/HSP 和 native 模块要在真实的加载、体积或复用需求出现后再引入。

推荐的 H1 最小闭环：

```text
DevEco Studio
  -> 新建 ArkTS Empty Ability
  -> 下载匹配 API 的 Phone image
  -> 创建 Phone emulator
  -> build + deploy + 调试一页静态 UI
  -> 记录 IDE / SDK / API / image / emulator 型号
```

这一步只证明工具链，不证明 RDB、同步、日历权限或发布能力。

## 3. 仓颉：官方事实、流程与项目门槛

### 3.1 目前可确认的官方事实

截至本知识库核对日，官方仓颉 HarmonyOS 应用入门指引明确写有：

- HarmonyOS 应用仓颉插件处于公开测试，需要申请测试权限；审核后再获取对应下载项。
- 指引示例的配套版本是 **DevEco Studio 5.0.0 Release** 与 **DevEco Studio-Cangjie Plugin Beta2 (5.0.3.906)**；这是示例，不是允许将任意最新 IDE 和任意插件组合的保证。
- 插件从本地磁盘安装，安装后重启 IDE；工程初始化会配置仓颉 SDK。
- 默认仓颉 SDK 目录：macOS `~/.cangjie-sdk`；Windows `%USERPROFILE%/.cangjie-sdk`。可在安装插件前设置 `DEVECO_CANGJIE_PATH`，并重启 DevEco Studio 生效。
- 新建工程选择 `[Cangjie] Empty Ability` 或 `[Cangjie] Hybrid Project`；IDE 每个运行窗口建议保留至少 2 GB 可用内存。
- 仓颉 IDE 插件宣称提供工程管理、编码辅助、编译构建、HAP 推送和断点调试；其中 HarmonyOS 调试能力必须在当前插件版本与目标设备上再次实测。

### 3.2 仓颉 H1 受控实验清单

1. 注册/登录华为开发者账号，申请并确认仓颉公测资格；不把账号 Cookie、下载令牌、证书或 Profile 写入仓库。
2. 从同一官方版本组合页面获取 DevEco Studio 与 Cangjie Plugin，记录文件名、版本、下载日期和校验方式。
3. 先用 ArkTS Hello World 验证 DevEco Studio、SDK manager、模拟器和网络环境；这能区分 IDE 问题和仓颉插件问题。
4. 安装本地插件并重启 DevEco；如需自定义 SDK 路径，在安装前设定 `DEVECO_CANGJIE_PATH`。路径只记录在开发机私有笔记或 `.env.local`，不得提交。
5. 新建 `[Cangjie] Empty Ability`，不从现有 Apple 仓库复制任何源码；初始化完成后记录自动生成的模块、构建配置、扩展名和锁文件。
6. 选择匹配的 Phone 模拟器，完成 debug build、推包、冷启动、热重启、断点与日志读取。
7. 新增一个无隐私数据的 RDB CRUD spike 和一个 ArkUI 页面调用；检查异常、并发与资源释放语义。该 spike 必须放在独立实验仓库或忽略目录，验收完成后只保留结果，不混入产品工程。
8. 只有上述证据完整，才由架构评审决定仓颉是否承担某个**隔离模块**。若有任一项不稳定，产品实现继续采用 ArkTS。

## 4. “如何用仓颉编译”的正确口径

仓颉的 HarmonyOS 应用不是把 `.cj` 文件交给一个通用 `cjc` 命令就可以替代整个 App 构建。官方应用路径由 **DevEco Studio + 匹配的 Cangjie Plugin + 工程模板** 承担：插件负责工程初始化/SDK 配置，IDE 负责构建、推包与设备运行。通用仓颉工具链中的 `cjc` / `cjpm` 文档可用于理解语言包与非应用项目的编译，但不能据此假定 HarmonyOS HAP 产物、签名、模块图和部署过程可脱离 DevEco 工程。

因此项目 CI 的先后顺序是：

1. 先在 DevEco Studio 的受支持版本上生成并成功运行一个仓颉工程。
2. 导出/确认该版本实际支持的命令行构建入口与构建产物位置。
3. 将该命令、版本锁定方式、网络依赖、缓存路径和失败日志最小化写进 `harmonyos/README.md`。
4. 再接入 CI。不要猜测 `hvigorw`、插件任务名或 HAP 输出路径；以实际生成项目与该版本官方文档为准。

```markdown
- HarmonyOS SDK API / build-tools version:
- Cangjie plugin version and preview entitlement confirmed:
- Cangjie SDK version/path (path redacted):
- Device image / emulator type / image version:
- ArkTS Hello World: build / deploy / debug evidence:
- Cangjie Empty Ability: build / deploy / debug evidence:
- Known blockers and official ticket/reference:
```

没有该记录，任何“仓颉已接入知行”的说法都不成立。
