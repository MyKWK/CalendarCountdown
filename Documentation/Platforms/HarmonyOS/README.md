## 当前结论

- **首个可发布客户端的默认语言：ArkTS + ArkUI。** 华为官方仍将 ArkTS 描述为 HarmonyOS 应用开发的优选主力语言，DevEco Studio 是推荐 IDE。
- **仓颉是受控试验路线，不能取代 ArkTS 基线。** 官方仓颉 HarmonyOS 指引仍要求申请公测权限、安装匹配的 DevEco Studio 仓颉插件，并且该指引所举版本组合为 DevEco Studio 5.0.0 Release + Cangjie Plugin Beta2。每次工具升级都要重新核对兼容矩阵。
- **“仓颉能编译”不等于“仓颉适合当前产品”。** 第一项仓颉验收必须明确验证：能否创建 `[Cangjie] Empty Ability`、phone emulator 是否支持、调试是否可用、与所需 ArkUI/Kit API 的互操作边界，以及构建产物能否进入 CI。
- **模拟器是开发门槛，不是发布证据。** 预览器/模拟器调试通常免签名，但真机调试、系统权限、后台、性能、应用市场上架与实际账号云服务必须单独验收。

## 本项目的非协商约束

1. macOS 是主力，iOS/iPadOS 是次主力；它们正在开发，不能因鸿蒙探索被切分、重置或重构。
2. 鸿蒙端以同一产品合同接入，不复制 Swift 实现、不直接依赖 CloudKit，也不把系统日历 ID 当作跨端 ID。
3. 未在真机确认的系统日历、提醒、后台或云能力，文档中统一标注为“待验证”，不作产品承诺。
4. 构建目录、下载镜像、SDK、日志和签名材料均是本机环境资产，不放入 Git。

## 查阅与更新规则

- 官方文档会随 HarmonyOS API、DevEco Studio、仓颉插件版本变动。本目录记录结论、版本配对风险与可执行验收步骤，不复制受版权/版本影响的大段官方内容。
- 开启 H1 前，由实施者重新打开 [SOURCES.md](SOURCES.md) 中的所有标记为“需实时核验”的链接，在 `STATUS.md` 增补实际 IDE、SDK、API Level、镜像、主机架构和验证日期。
- 资料更新与代码初始化分开提交；仓颉资料更新不代表已批准仓颉作为产品语言。
