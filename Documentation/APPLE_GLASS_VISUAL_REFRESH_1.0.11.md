# 知行 1.0.11 Apple Glass 视觉升级执行方案

## 1. 产品目标

把“知行”从功能完整但视觉偏工具化的界面，升级为安静、精密、可信赖的 Apple 原生个人执行系统。

本次不是给整个窗口增加透明度，也不是套用大量彩色卡片。目标是通过清晰的信息层级、克制的材质、统一的空间节奏和少量有物理感的交互，让产品呈现高端、耐看、长期可用的质感。

核心关键词：**克制、通透、精密、安静、可信赖**。

## 2. 本版范围

- 版本目标：`1.0.11`，构建号在当前构建号上递增。
- macOS 主窗口是本版主要验收对象。
- 设计 token 和基础组件应写成可供 iPhone/iPad 复用的 SwiftUI 实现；不得破坏已有移动端编译。
- 保留四个一级入口：倒数日、任务清单、使命清单、打卡。
- 不修改数据模型、数据库 schema、同步语义、EventKit 投影规则、CLI 合同或菜单栏业务逻辑。
- 不新增“今天”作为第五个一级入口。
- 保持 `mac-icloud-sync-control` 与 `mac-settings-button` 独立，保留现有可访问性标识和关键 UI 测试合同。
- 不触碰用户未跟踪文件 `Documentation/BRANCH_AND_RELEASE_POLICY_DRAFT.md`。

## 3. 视觉原则与禁区

### 3.1 局部材质，不做全窗穿透

- 不重新启用 `WindowGlassAppearance.userFacingEnabled`。
- 不允许桌面壁纸穿透列表正文、编辑表单或大面积内容区。
- 玻璃材质只用于侧栏选择、工具栏分组、浮层状态、少量高价值摘要卡与交互控件。
- 内容正文应有稳定、可读的实色或高不透明度基底。
- 尊重 Reduce Transparency、Reduce Motion、Increase Contrast 和系统浅色/深色模式。

### 3.2 层级来自排版和空间

- 页面标题、主内容、元信息、状态提示建立明确的四级层次。
- 避免通过增加边框、阴影、彩色背景表达所有层级。
- 删除装饰性噪声；红色和橙色只表达逾期、失败与风险。

### 3.3 一致而非同质

- 四个模块共享圆角、间距、字号、材质与状态反馈。
- 倒数日可以突出时间数字，任务突出完成动作，使命突出进度，打卡突出连续性；允许业务重心不同，但视觉语法必须一致。

## 4. 设计系统

新建集中式 SwiftUI 视觉基础文件，例如 `Source/App/ZhixingDesignSystem.swift`。命名可调整，但不能把 magic number 分散到多个页面。

### 4.1 间距

- `space4 = 4`
- `space8 = 8`
- `space12 = 12`
- `space16 = 16`
- `space20 = 20`
- `space24 = 24`
- `space32 = 32`

页面水平安全边距以 20–24 pt 为主；列表内部不得忽大忽小。

### 4.2 圆角

- 小控件：8 pt
- 胶囊：连续圆角
- 摘要/使命容器：14–16 pt
- Sheet 内容组：12 pt

统一使用 continuous corner style。不得同时出现大量 5、10、12、18 等无体系值。

### 4.3 描边、阴影与材质

- 玻璃/高价值容器：`ultraThinMaterial` 或 `thinMaterial`，叠加 0.5–1 px 的白色/主色低透明高光描边。
- 普通内容容器：系统背景的高不透明度层，不默认加阴影。
- 阴影只用于悬浮层；深色模式中不得用大面积黑色重阴影。
- 主色染色面积小于容器面积的约 15%，使命色仅用于图标、细进度、标签或微光。

### 4.4 动效

- 状态切换使用 160–240 ms 的 snappy/easeInOut 动画。
- 完成任务、展开使命、切换侧栏可以有轻微缩放/淡入，但不得持续弹跳。
- Reduce Motion 开启时退化为淡入淡出或无动画。

## 5. 主窗口信息架构

### 5.1 侧栏

- 保留当前四项与数量 badge。
- 降低未选中图标和数字的对比度；选中项使用单层柔和玻璃胶囊，减少高饱和青色实心填充。
- 选中状态可采用强调色的低透明度光晕/描边，但文字仍保持系统主文字色。
- 侧栏宽度建议 220–248 pt；保持足够呼吸感但不侵占主内容。
- 侧栏底部可放一条极轻量的本地/iCloud 状态摘要，但不能替代工具栏同步控制，也不能造成两个开关。

### 5.2 工具栏

- 降低“每个操作都并排占一个按钮”的拥挤感。
- 主操作仅保留一个清晰的“新建”按钮，并随当前模块变化。
- 导入、导出、刷新、系统投影收敛为语义清楚的次级菜单或分组；不要删除能力。
- iCloud 状态与设置继续独立；iCloud 使用小型状态胶囊，明确显示“仅本机 / 已同步 / 同步中 / 失败”。
- 搜索保留在右侧，但视觉权重低于主操作。
- 所有工具栏按钮保留 help、keyboard shortcut、accessibility label。

### 5.3 页面标题区

- 正文顶部加入统一的模块 header：标题 + 一句简短描述/状态摘要 + 必要的模块级操作。
- 不重复显示窗口标题与页面大标题造成噪声；通过 macOS NavigationSplitView 的原生行为协调。
- 标题区不使用大面积渐变 banner。

## 6. 模块改造

### 6.1 倒数日

- 列表首项作为“最近倒数”焦点行：更大的倒数数字、日期与事件标题，使用高不透明度的轻玻璃摘要容器。
- 其余事件保持紧凑列表，不做 23 张独立卡片。
- 每行建立三层：标题；日期/分类；右侧倒数数字。
- 左侧日历色改成 3–4 pt 的细标识或小圆点，不能成为粗彩色条。
- 收藏与更多操作降低常驻视觉权重，hover/focus 时更清楚；可访问性操作保持可发现。

### 6.2 任务清单

- 从“系统表格行”升级为无重边框的分组列表：标题是主信息，描述最多两行，使命/时间/工作量用统一 tag/meta 样式。
- 完成按钮为 20–22 pt 的精致圆环；完成后使用柔和的打勾、轻微淡化与短动画。
- 逾期只染色时间或“逾期”标签，不让整行变红。
- 已完成任务不可因视觉刷新从数据源中消失；保留编辑、跳过、归档和上下文菜单行为。
- 行间分隔使用缩进、低对比度 separator 或 8 pt 空间，避免横线铺满整个窗口。

### 6.3 使命清单

- 保留卡片结构，但显著降低大面积使命色背景；使用中性高不透明度底 + 使命色小面积身份标识。
- 图标、名称、状态、截止日期组成稳定 header。
- 进度作为最主要的视觉数据：细进度轨道 + 百分比 + 完成点数，数字使用 monospacedDigit。
- 展开后的任务列表不应让卡片像表单堆叠；子任务视觉比使命标题低一级。
- 编辑、暂停、归档、删除等管理动作收进清晰的 overflow/context menu；危险操作不常驻为同权按钮。
- 保留双击折叠、添加任务、关联已有任务、完成使命等业务能力与可访问性 ID。

### 6.4 打卡

- 有数据时以“今日状态 + 连续性”为重心：大而克制的打卡控件、连续天数、周期完成情况。
- 空状态不只显示图标和说明；提供一个清晰主操作“新建打卡”，并保持新建业务入口可用。
- 多个习惯使用和任务一致的中性列表语言，颜色只表示习惯身份和完成状态。

## 7. Sheet、空状态与反馈

- 新建/编辑 Sheet 统一：标题区、内容分组、固定底部操作区；取消为次级，保存/创建为唯一主按钮。
- 表单中的 Markdown、日期、重复规则和使命关联功能不得退化。
- 所有空状态统一使用 SF Symbol、简短标题、一句说明和最多一个主操作。
- 成功提示使用底部悬浮玻璃胶囊；错误继续使用可理解的显式 alert，不得仅通过颜色表达。
- iCloud 启动失败必须回到仅本机并展示明确错误，不能假装已启用。

## 8. 工程实现要求

- 优先使用 SwiftUI 和系统颜色/材质/SF Symbols；不要引入第三方 UI 依赖。
- 提取可复用组件，例如：`GlassSurface`、`ModuleHeader`、`MetaTag`、`StatusCapsule`、`PrimaryToolbarAction`。实际命名可调整。
- 不做侵入式 AppKit 视图树遍历来强制所有 `NSScrollView`/`NSTableView` 透明。
- 组件必须支持浅色、深色、高对比度和降低透明度。
- 保留或补充 accessibilityIdentifier；现有 UI 测试依赖标识不得无理由改名。
- 避免因 `List`、`Button` 或 `NavigationSplitView` 样式变化导致点击区域缩小、键盘导航失效或上下文菜单丢失。

## 9. 验收门槛

### 9.1 视觉验收

- 深色和浅色模式分别检查四个模块、设置页和至少一个新建/编辑 Sheet。
- 无桌面壁纸穿透正文，无大面积低可读性透明层。
- 工具栏主次关系明确；“新建”是唯一高权重动作。
- 四个模块能看出统一设计系统，使命色不再大面积铺底。
- 小窗口、默认窗口和较宽窗口下无截断、重叠或无法点击。

### 9.2 功能回归

- 四个一级入口、搜索、新建、编辑、完成、跳过、折叠、上下文菜单、导入、导出、刷新、系统投影、iCloud 控制和设置仍可用。
- 已完成任务仍按当前产品合同显示，不因筛选数据源错误而消失。
- iCloud 与设置仍是独立 UI；失败状态真实、显式。
- macOS 单元测试、iOS Simulator 编译和现有 UI 测试通过。

### 9.3 发布验收

- 更新到 1.0.11 并添加发布说明。
- 实现阶段先完成测试与人工 GUI 验收；在确认代码符合本方案后执行 `Source/Scripts/release-local.sh`。
- 发布流程必须完成清理、macOS 测试、iOS Simulator 编译、Universal DMG、`Releases/1.0.11/` 归档与 SHA-256、替换 `/Applications/知行.app`、签名及版本检查。
- 本地构建和安装不等于真实 CloudKit、跨设备同步或公证通过；这些证据边界必须单独报告。

## 10. 实施顺序

1. 建立设计 token 与基础组件，不改变页面功能。
2. 改造侧栏、工具栏和全局反馈。
3. 改造倒数日与任务清单。
4. 改造使命清单与打卡。
5. 统一 Sheet、设置页和空状态。
6. 补充/更新测试，执行 macOS 与 iOS 编译验证。
7. 由 Codex 独立检查 diff、真实 GUI 和回归结果；不符合项退回修正。
8. 验收通过后执行完整本地发布。

## 11. 完成定义

只有同时满足以下条件才算完成：

- 代码实现与本方案一致，而不是仅增加透明背景。
- 四个模块、工具栏、侧栏、反馈和 Sheet 使用统一视觉语言。
- 业务能力与数据语义无回归。
- 自动化测试与目标编译通过。
- Codex 完成真实 GUI 检查。
- 1.0.11 Universal DMG 已归档并安装替换，版本和签名检查通过。
