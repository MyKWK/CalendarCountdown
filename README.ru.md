## Что это за проект

CalendarCountdown — не ещё одна база данных календаря. Учётные записи, календари, события и цвета остаются под управлением Календаря Apple. Проект читает и записывает разрешённые пользователем календари через EventKit и решает одну задачу: делает важные даты видимыми, вычисляемыми, экспортируемыми и удобными для автоматизации.

## Основные возможности

- Читает разрешённые календари Apple, сохраняя их учётные записи, категории и цвета.
- Отслеживает дни рождения, годовщины, праздники и разовые важные даты.
- Поддерживает ежегодные правила григорианского и китайского лунного календарей, включая дополнительные месяцы и коррекцию коротких лунных месяцев.
- Вычисляет «сегодня», «завтра» и оставшееся количество дней по локальному системному календарю.
- Предоставляет нативное приложение macOS, представление в строке меню и настольный виджет WidgetKit.
- Интерфейс приложения, меню и виджетов следует языку macOS: упрощённый китайский, английский, японский, корейский, испанский или русский.
- Добавляет обычные события, дни рождения по григорианскому или лунному календарю в явно выбранный календарь Apple.
- Экспортирует все отслеживаемые важные даты одним действием.
- Универсальный бинарный файл для Mac с Apple Silicon и Intel; требуется macOS 14 или новее.

## Разработано для ИИ-агентов

`calcount` — локальный интерфейс командной строки, который можно напрямую предоставить агенту как shell-инструмент. Все структурированные команды выводят JSON без интерактивного текста, а явные коды завершения различают ошибки параметров, отсутствие разрешения календаря и ошибки выполнения.

Свойства, удобные для агентов:

- **Предсказуемое чтение:** список календарей, запрос событий, получение ближайших отсчётов и чтение индекса отслеживания.
- **Стабильные JSON-конверты:** успех — `{ "ok": true, "data": ... }`, ошибка — `{ "ok": false, "error": { "code": ..., "message": ... } }`.
- **Контролируемая запись:** операции записи требуют явно указанного календаря Apple; пакетный импорт поддерживает `--dry-run`.
- **Идемпотентный импорт:** `externalId` предотвращает дублирование, если агент повторяет запрос.
- **Переносимый контекст:** `tracked-events.json` сохраняет начальный год, систему календаря, месяц и день, правила повторения, следующую дату и ссылки на Календарь Apple.
- **Локальная архитектура:** сервер и облачная копия календаря не нужны. Агент обращается только к данным EventKit, разрешённым на текущем Mac.

Основные команды чтения и экспорта:

```bash
./calcount doctor
./calcount calendars list
./calcount events list --days 365
./calcount next --limit 10 --days 3653
./calcount tracking refresh
./calcount tracking list
./calcount tracking export --output tracked-events.json
```

Агент может напрямую обрабатывать результат с помощью `jq`:

```bash
./calcount next --limit 5 | jq '.data[] | {title, eventDate, calendarTitle}'
```

Предварительная проверка пакетного импорта перед записью:

```bash
./calcount import /path/to/import.json --dry-run
```

Сейчас `calcount` предоставляет локальный контракт CLI. Проект не заявляет о наличии MCP-сервера или удалённого API, но любой агентный фреймворк с поддержкой shell-инструментов может подключить его как инструмент.

## JSON отслеживаемых дат

Календарь Apple всегда остаётся источником истины для содержимого событий. `tracked-events.json` — не вторая база календаря, а версионируемый и экспортируемый индекс элементов, видимых в интерфейсе обратного отсчёта.

Каждая запись содержит:

- Стабильный UUID, название и тип: день рождения, годовщина, важная дата или другое.
- Начальный год, месяц, день и признак григорианского/лунного календаря.
- Частоту повторения, календарь повторения и правила обработки граничных случаев лунного календаря.
- Следующую дату, время, часовой пояс и признак события на весь день.
- Источник, календарь, цвет и идентификаторы Календаря Apple для повторной привязки.
- Режим отслеживания, время начала отслеживания и состояние закрепления.

Полный анонимный пример: [tracked-events.example.json](Documentation/tracked-events.example.json).

## Установка

Текущая версия: **1.0.1**

1. [Скачайте CalendarCountdown-1.0.1-macos-universal.dmg из GitHub Releases](https://github.com/MyKWK/CalendarCountdown/releases/download/v1.0.1/CalendarCountdown-1.0.1-macos-universal.dmg).
2. Перетащите CalendarCountdown в папку «Программы».
3. Запустите приложение и предоставьте полный доступ к Календарю Apple.

Сборка 1.0.1 использует временную ad-hoc подпись и не подписана Apple Developer ID и не нотарифицирована. При первом запуске может потребоваться щёлкнуть приложение в Finder с удержанием Control и выбрать «Открыть».

## Сборка из исходного кода

Требуются macOS 14+, Xcode и [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
cd Source
./Scripts/bootstrap.sh
./Scripts/build.sh
xcodebuild -project CalendarCountdown.xcodeproj \
  -scheme CalendarCountdown \
  -configuration Debug \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath DerivedData \
  CODE_SIGNING_ALLOWED=NO test
./Scripts/package-dmg.sh
```

## Границы данных и конфиденциальности

- События остаются в Календаре Apple; проект не запускает собственный облачный календарный сервис.
- Выбор отслеживания и `tracked-events.json` остаются на Mac для отображения и экспорта по инициативе пользователя.
- Запись затрагивает только календарь Apple, явно выбранный пользователем.
- Файлы с реальными личными датами исключены через `.gitignore` и не должны попадать в публичный репозиторий или пакет выпуска.

## Текущие границы

- Сейчас поддерживается macOS. Приложение для iPhone, виджеты iPhone и синхронизация правил через CloudKit относятся к будущим этапам.
- Проект не является сервером CalDAV и не копирует структуру учётных записей и категорий Календаря Apple.
- Подробный контракт продукта и данных: [Documentation/PRODUCT.md](Documentation/PRODUCT.md).
